# Milestone 2: Upload Implementation Plan

> **How this plan is executed:** learning mode, not an autonomous agent run. One task at a time, in small steps, with a stop for review after each. Each task has a **Who** line: `Claude` writes boilerplate and UI; `Nikhil` writes interview-critical code from the signatures and tests here, or reviews Claude's version with a planted bug, as he chooses per task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A user drops a video in the browser and it lands in object storage in chunks, sent straight from the browser, with bad files and exhausted quotas rejected.

**Architecture:** The API never receives video bytes. It opens an S3 multipart upload, signs one short-lived URL per chunk, and closes the upload when the browser reports every chunk done. Storage sits behind a `Storage` interface with an S3 implementation (MinIO locally) and an in-memory one for tests.

**Tech Stack:** boto3 (S3 API against MinIO), FastAPI, Next.js. Builds on Milestone 1.

**Spec:** `docs/superpowers/specs/2026-10-04-snipwise-design.md`

## Global Constraints

- All Milestone 1 constraints still apply (error shape, owner scoping, camelCase JSON, `/api` prefix).
- Upload limits: at most 2 GB (`2 * 1024**3` bytes), content type `video/mp4` or `video/quicktime` only.
- Part size is 8 MB (`8 * 1024**2`). S3 requires every part except the last to be at least 5 MB.
- Presigned URL lifetimes: 15 minutes for upload parts, 5 minutes for downloads.
- Object keys are built from ids only. The source video is `projects/{project_id}/source`. The original filename never appears in a key.
- boto3 is synchronous. In the API, every boto3 call that touches the network runs through `run_in_threadpool`. Presigning is local and may be called directly.
- Files expire 7 days after the upload completes (`files_expire_at`).

## Review Focus

1. `complete` called with wrong or missing ETags returns a clear 422, not a 500 (Task 2).
2. The uploaded object's real size differs from the declared size: the upload is rejected and removed (Task 2).
3. `start` called twice for the same project aborts the first upload instead of leaking it (Task 2).
4. A zero-byte file is rejected at `start` with 422 (Task 2).
5. A filename with spaces, unicode or `../` has no effect on where the file is stored (Task 2).

    ```python
    @dataclass(frozen=True)
    class UploadedPart:
        part_number: int
        etag: str

    class StorageError(Exception): ...          # anything the store rejects (bad ETag, unknown upload)

    class Storage(Protocol):
        def create_multipart_upload(self, key: str, content_type: str) -> str: ...        # returns upload_id
        def presign_upload_part(self, key: str, upload_id: str, part_number: int, expires_sec: int = 900) -> str: ...
        def complete_multipart_upload(self, key: str, upload_id: str, parts: list[UploadedPart]) -> None: ...
        def abort_multipart_upload(self, key: str, upload_id: str) -> None: ...             # no error if already gone
        def object_size(self, key: str) -> int | None: ...                                   # None if missing
        def presign_download(self, key: str, expires_sec: int = 300, filename: str | None = None) -> str: ...
        def download_file(self, key: str, dest: Path) -> None: ...
        def upload_file(self, src: Path, key: str, content_type: str) -> None: ...
        def delete_prefix(self, prefix: str) -> None: ...
        def delete_object(self, key: str) -> None: ...
    ```

**Interfaces:**
- Consumes: `get_storage()`, `OwnedProject`, `CurrentUser`, `transition`, `minutes_used_this_month`, `settings`.
- Produces:
  - `POST /api/projects/{id}/upload/start` body `{filename: str 1..255, sizeBytes: int, contentType: str}` → 200 `{uploadId, partSize, partCount}`.
    - Project must be in `uploading`, else 409 `invalid_state`.
    - `sizeBytes <= 0` → 422. `sizeBytes > max_upload_bytes` → 413 `payload_too_large`. Content type not `video/mp4` or `video/quicktime` → 422 `unsupported_type`.
    - `minutes_used_this_month >= free_minutes_per_month` → 403 `quota_exceeded`.
    - If the project already has an `upload_id`, abort that upload first.
    - Saves `upload_id`, `source_key = f"projects/{id}/source"`, `source_size_bytes`. `partCount = ceil(sizeBytes / upload_part_bytes)`.
  - `POST /api/projects/{id}/upload/sign-part` body `{partNumber: int}` → 200 `{url}`. No active upload → 409 `invalid_state`. `partNumber` outside `1..partCount` → 422.
  - `POST /api/projects/{id}/upload/complete` body `{parts: [{partNumber, etag}]}` → 200 `ProjectOut`.
    - Completes the multipart upload. `StorageError` → 422 `upload_incomplete`.
    - `object_size(source_key) != source_size_bytes` → delete the object, clear `upload_id`, 422 `size_mismatch`.
    - `transition(to=uploaded, from_=[uploading])`; `False` → 409 `invalid_state`.
    - Sets `files_expire_at = now + 7 days`, clears `upload_id`.
  - `POST /api/projects/{id}/upload/abort` → 204. Aborts if an upload is active; always 204.
  - `DELETE /api/projects/{id}` now also aborts any active upload and calls `delete_prefix(f"projects/{id}/")`.
  - `uploads.exceptions`: `InvalidState` (409, `invalid_state`), `QuotaExceeded` (403, `quota_exceeded`, "You have used all your minutes for this month."), `UnsupportedType` (422, `unsupported_type`), `UploadIncomplete` (422, `upload_incomplete`), `SizeMismatch` (422, `size_mismatch`).

    ```ts
    export type UploadHandle = { promise: Promise<void>; abort: () => void };
    export function uploadVideo(projectId: string, file: File, onProgress: (fraction: number) => void): UploadHandle;
    ```
